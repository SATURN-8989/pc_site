# Домашнее задание: Протокол HTTP, клиент-серверная модель и разбор запросов

---

### 1. Определение базовых терминов

1. **HTTP (HyperText Transfer Protocol)** — протокол прикладного уровня передачи данных, изначально разработанный для пересылки гипертекстовых документов (HTML-страниц). Его главное назначение — обеспечение связи и обмена данными между веб-клиентом (браузером) и веб-сервером.
2. **HTTPS (HyperText Transfer Protocol Secure)** — расширение протокола HTTP, поддерживающее шифрование данных. Главное отличие от HTTP заключается в том, что все передаваемые данные упаковываются в криптографический протокол TLS/SSL. Это защищает трафик от перехвата и изменения злоумышленниками.
3. **Клиент-серверная модель** — архитектура сетевого взаимодействия, в которой устройства разделены на две роли: клиенты и серверы. Клиент (например, браузер) инициирует сеанс и отправляет запрос на предоставление услуги или данных, а сервер принимает запрос, обрабатывает его и возвращает соответствующий ответ.
4. **Идемпотентность** — свойство метода (запроса) протокола HTTP, при котором повторение одного и того же запроса несколько раз подряд приводит к тому же результату, что и при однократном выполнении. Повторные идемпотентные запросы не изменяют состояние сервера (например, методы GET, PUT, DELETE).

### 2.1. Разбор HTTP-запроса

Ответы на вопросы по представленному HTTP-запросу:

1. **Какой метод используется?**
   Используется метод POST.
2. **Какой путь (endpoint) запрашивается?**
   Запрашивается путь `/api/users`.
3. **Какая версия HTTP?**
   Версия протокола HTTP/1.1.
4. **Что означает заголовок Content-Type?**
   Этот заголовок указывает серверу формат данных, передаваемых в теле запроса. Значение `application/json` означает, что данные передаются в формате JSON.
5. **Что означает заголовок Authorization?**
   Этот заголовок используется для аутентификации клиента на сервере. Значение `Bearer eyJhbGci...` передает серверу специальный токен доступа (JWT) для проверки прав пользователя.
6. **Где находится тело запроса?**
   Тело запроса находится в самом конце, отделенное от заголовков пустой строкой. В данном случае это строка: `{"name": "Иван", "email": "ivan@mail.com"}`.

---

### 2.2. Разбор HTTP-ответа

Ответы на вопросы по представленному HTTP-ответу:

1. **Что означает статус-код 201?**
   Статус-код `201 Created` означает, что запрос выполнен успешно и в результате на сервере был создан новый ресурс.
2. **Зачем нужен заголовок Location?**
   Заголовок Location указывает точный URL-адрес (путь), по которому теперь доступен только что созданный на сервере ресурс. В данном примере это `/api/users/42`.
3. **Что находится в теле ответа?**
   В теле ответа находится созданный объект в формате JSON, содержащий присвоенный идентификатор и данные пользователя: `{"id": 42, "name": "Иван", "email": "ivan@mail.com"}`.

### 2.3. Самостоятельное составление HTTP-запросов

Ниже приведены примеры HTTP-запросов, составленные для различных операций с ресурсом товаров (`products`).

#### Получение списка всех товаров
```http
GET /api/products HTTP/1.1
Host: example.com
Accept: application/json
```

#### Создания нового товара с именем "Ноутбук" и ценой 50000
```http
POST /api/products HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: 46

{
  "name": "Ноутбук",
  "price": 50000
}
```

#### Удаления товара с id=7
```http
DELETE /api/products/7 HTTP/1.1
Host: example.com
```

#### Обновления товара с id=3 (изменить цену на 45000)
```http
PATCH /api/products/3 HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: 17

{
  "price": 45000
}
```
