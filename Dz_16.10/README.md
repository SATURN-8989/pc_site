# Подробный конспект по дисциплине Информационные технологии и сетевые протоколы
## Тема Архитектура службы доменных имен DNS и принципы конфигурации ресурсных записей зон

### 1 Исторические предпосылки создания и эволюция систем адресации хостов
* **Период ручного администрирования в ARPANET** В эпоху зарождения первой компьютерной сети ARPANET вся топологическая информация о сетевых узлах фиксировалась в единой текстовой базе данных вручную Данная система напоминала глобальную статическую таблицу сопоставления имен и числовых адресов хостов Для добавления нового сетевого ресурса администратору требовалось осуществлять телефонный звонок в центральный информационный узел для внесения записи оператором
* **Кризис масштабирования и переход к автоматизации** С ростом масштабов вычислительной сети ручное ведение текстовых файлов сопоставления стало физически невозможным из за колоссального объема новых узлов Для устранения ручного труда и обеспечения автоматического сопоставления символьных имен сайтов и числовых IP адресов разработчиками была спроектирована распределенная иерархическая система доменных имен DNS

### 2 Концепция функционирования DNS и иерархическая структура доменов
* **Сущность протокола и распределенной базы данных** DNS представляет собой глобально распределенную базу данных работающую на прикладном уровне модели OSI Она функционирует по принципу телефонного справочника где каждому понятному человеку доменному имени строго соответствует числовой IP адрес сетевого узла необходимый браузерам и маршрутизаторам для коммутации пакетов
* **Иерархия доменных уровней** Доменные имена обладают жесткой древовидной структурой уровни которой перечисляются в адресной строке строго справа налево
  * **Домен нулевого уровня** Является корневым root доменом обозначается символом точки на конце адреса скрыт от рядовых пользователей но критически необходим для функционирования корневых серверов
  * **Домен первого уровня** Представляет собой доменную зону Сюда относятся национальные зоны привязанные к территориям государств такие как ru de uk а также общие тематические зоны generic TLD включая com для коммерческих структур info для информационных ресурсов и org для некоммерческих организаций
  * **Домен второго уровня** Выступает основным уникальным именем веб ресурса которое придумывается создателем сайта и регистрируется через специализированные аккредитованные организации
  * **Домен третьего уровня** Называется субдоменом или поддоменом и применяется администраторами для логического разделения крупного сетевого ресурса на независимые функциональные или региональные части

### 3 Инфраструктура серверов и механизмы кэширования запросов
* **Архитектура корневых серверов** Вся мировая сеть опирается на 13 главных корневых DNS серверов содержащих информацию обо всех зонах интернета Для защиты от отказов аппаратных сбоев и хакерских атак создана разветвленная сеть из 123 серверов копий распределенных по планете В Российской Федерации функционируют пять серверов копий расположенных в Москве Санкт Петербурге Ростове на Дону Екатеринбурге и Новосибирске
* **Алгоритм обработки DNS запроса** При вводе пользователем адреса в строку браузера операционная система сначала проверяет локальный файл конфигурации hosts содержащий базу предыдущих посещений При отсутствии записи запрос перенаправляется на локальный DNS сервер интернет провайдера который циклически опрашивает региональные узлы до получения точного ответа
* **Технология кэширования** При получении целевого адреса локальный сервер провайдера сохраняет его в свою промежуточную память кэш Это снижает общую нагрузку на магистральные каналы связи и ускоряет повторный запуск страниц пользователями Кэш обладает ограниченным временем жизни TTL после истечения которого записи обновляются автоматически

### 4 Типы ресурсных записей и структура файлов описания DNS зоны
Связи между доменными именами и сетевыми параметрами хостов кодируются в текстовых файлах зон с помощью специализированных ресурсных записей
* **Запись А** Ключевой тип записи сопоставляющий стандартное имя хоста с его классическим числовым IPv4 адресом
* **Запись MX** Отвечает за маршрутизацию электронной почты и указывает адреса почтовых серверов обслуживающих данный домен
* **Запись CNAME** Каноническое имя или запись для создания псевдонимов которая перенаправляет запросы с поддоменов на основной родительский домен
* **Запись NS** Содержит точный адрес DNS сервера на котором физически размещены все остальные ресурсные записи текущей зоны
* **Запись TXT** Хранит сопутствующую текстовую информацию домена используемую для верификации прав на сайт и защиты от спама

### 5 Структура и формат SOA записи как начала зоны управления
* **Назначение SOA записи** Запись Start Of Authority Начало Зоны является строго обязательной базовой структурой в файлах описания зон Без наличия SOA записи функционирование доменной зоны и синхронизация серверов внутри кластеров становятся технически невозможными Она регулирует параметры передачи зон между первичными и вторичными серверами
* **Формат и параметры конфигурации SOA записи на примере сервера Bind**
  * **Primary Name Server** Символьное имя главного первичного DNS сервера текущей доменной зоны
  * **Hostmaster** Контактный адрес электронной почты системного администратора ответственного за зону где символ коммерческого эт заменяется обычной точкой
  * **Serial number** Уникальный серийный номер файла зоны представленный в виде 32 разрядного целого числа которое автоматически инкрементируется увеличивается при любом обновлении параметров сайта
  * **Refresh** Временной интервал в секундах который выжидает вторичный DNS сервер перед отправкой запроса к первичному серверу для проверки обновлений файла зоны
  * **Retry** Время ожидания в секундах по истечении которого вторичный DNS сервер обязан повторить попытку связи если первичный сервер оказался временно недоступен
  * **Expire** Максимальный срок в секундах в течение которого вторичный сервер пытается завершить синхронизацию зоны Если за это время связь не восстановилась вторичный сервер прекращает обслуживание запросов пользователей по данной зоне
  * **Minimum TTL** Минимальное время жизни данных применяемое ко всем ресурсным записям текущей зоны и информирующее сторонние серверы о допустимом сроке хранения информации в их локальном кэше
